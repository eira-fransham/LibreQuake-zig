# Translating LibreQuake's QuakeC to Zig

`lq-zig` is a port of LibreQuake's NetQuake game code (`../../LibreQuake/qcsrc`)
to Zig. `zig-qc build` (from the parent `wasm-to-qc` project) compiles it to wasm,
converts that to QuakeC, and runs fteqcc on the result. The resulting `progs.dat`
must be **compatible with the original**:
- same entity fields, globals and function names (maps and savegames refer to
  them by name)
- same behaviour

It does not need to produce the same bytecode.

## Sources

- **Translate from the preprocessed copies in `/tmp/lqwork/pp/`, not from
  `qcsrc` directly.** `tools/preprocess.py` produced them with `__LIBREQUAKE__`
  defined and `__QW__` not, which is how LibreQuake's `build.py` builds NetQuake.
  Inactive branches are blank lines, so line numbers match the originals. Never
  translate QuakeWorld-only or non-LibreQuake code.
- `src/<file>.zig` already exists for every `<file>.qc`, generated by
  `tools/gen_stubs.py`. It declares the file's globals (`q.userGlobal`), fields
  (`q.userField`) and constants, the `Frame` enum, and one `pub export fn` stub
  per QuakeC function, with the right name and signature and a
  `// TODO(translate)` + `unreachable;` body. Your job is to replace the stub
  bodies with translations. Keep the generated names, signatures and
  declarations. If one is wrong, fix it and say so in your report.
- Things that aren't in your file:
  - `src/defs.zig` (`q`): the engine's system globals, the `Entity` struct
    with the system fields, builtins, and helpers. It's generated, so don't
    edit it.
  - `src/lq.zig` (`lq`): the game section of `defs.qc`. That's the constants
    (`lq.FL_ONGROUND`, `lq.IT_AXE`, `lq.CHAN_VOICE`, ...), globals
    (`lq.activator`, `lq.skill`, `lq.string_null`, ...), fields (`lq.th_die`,
    `lq.wait`, `lq.speed`, ...), and the NQ wrappers `lq.bprint(level, s)`,
    `lq.sprint(e, level, s)` and `lq.logfrag`. Use these wrappers, not
    `q.bprint` and `q.sprint`, wherever the QuakeC calls `bprint`/`sprint`
    with a level.
  - `src/localized_text.zig` (`loc`): the `LOC_*` strings.
  - Other modules: to find where a name lives, run `grep -rn "fn NAME(" src` or
    `grep -rn "const NAME =" src`. Import a module with
    `const ai = @import("ai.zig");`, or `@import("../ai.zig")` from
    `src/monsters/`. Name the import after the file. If that clashes with a
    parameter or local (Zig forbids shadowing), add `_qc` to the import's name
    instead.
- Worked examples: `src/subs.zig` and `src/buttons.zig` (complete). The QW port
  in `../qw-zig/src/` translates id's original versions of many of the same
  files and is a good reference for idioms. LibreQuake differs from id in many
  places, though, so always translate what LibreQuake's code says.

## Rules

- **Every QuakeC function stays `pub export fn` with its QuakeC name.** Anything
  that isn't exported gets an anonymous `__wasm_fN` name in the progs, which
  breaks savegames, maps (spawn functions) and the engine's entry points. If you
  need new Zig-only helpers, make them plain (non-exported) `fn`s, and don't
  give them QuakeC names.
- Functions used as values: `q.func(name)`. This is the form for `.think`,
  `.touch`, `.use`, `.blocked`, `th_*`, `SUB_CalcMove` callbacks, and so on.
  A function in another module is `q.func(mod.name)`. Compare function values
  with `q.fnEql`, `q.fnNeq` and `q.fnIsNull`.
- Function fields (system ones like `.think` and `.touch`, and user ones like
  `lq.th_die` and `lq.think1`) are `?Function`. They can hold QuakeC's null
  function, which is only a "no function" sentinel and can't be called.
  - `self.touch = __NULL__` is `self.touch = null`, and
    `self.th_pain = __NULL__` is `self.set(lq.th_pain, null)`.
  - Calling is `self.think.?()` or `self.get(lq.th_die).?()`. The QuakeC is
    usually already checking the field first.
  - Fields with parameters are called as
    `q.callAs(lq.ThPain, self.get(lq.th_pain).?)(attacker, damage)`.
  - Declare new function fields as `q.userField(?Function, "name")`.
  - Function *parameters* (`void() func`) stay non-optional `Function`.
- `self`, `other`, `activator` and other globals: read them with `.get()` and
  write them with `.set(v)`. `const self = q.me();` caches `self`. If the
  QuakeC reassigns `self` (`self = other;` and so on), use `q.self.set(...)` and
  re-read it afterwards. Never keep using a stale cached `self`.
- Entity fields: system fields are struct fields (`self.health`,
  `e.origin[2]`, `self.think = q.func(f)`). User fields use
  `self.get(lq.wait)` and `self.set(lq.wait, 1)`. `e.dest_x` becomes
  `e.get(lq.dest)[0]`. Setting one component of a user vector field is a
  read-modify-write of the whole vector, e.g.
  `var v = e.get(lq.dest); v[0] = 1; e.set(lq.dest, v);`.
- Types: `float` → `f32`, `vector` → `q.Vector` (use `q.vec(x, y, z)` for
  `'x y z'`), `string` → `q.String`, `entity` → `q.Entity`, `void()` →
  `q.Function`. QuakeC functions returning `float` return `f32`; return
  `lq.TRUE`/`lq.FALSE` and so on where the original does.
- Truthiness and comparisons:

  | QuakeC | Zig |
  |---|---|
  | float `if (x)` | `x != 0` |
  | string `if (s)`, `!s` | `!s.isNull()`, `s.isNull()` |
  | entity `if (e)`, `!e` | `!e.isNull()`, `e.isNull()` |
  | function `if (f)` | `!q.fnIsNull(f)` |
  | vector `if (v)` | `q.vtrue(v)` |
  | `a == b` on strings | `a.eql(b)` / `a.neq(b)` |
  | `a == b` on entities | `a.eql(b)` / `a.neq(b)` |
  | `a == b` on vectors | `q.veq(a, b)` |
  | `x & FLAG` | `q.band(x, FLAG)` |
  | `x \| FLAG` | `q.bor(x, FLAG)` |
  | `if (x & FLAG)` | `q.has(x, FLAG)` |
  | `vec * float` | `q.scale(v, f)` |
  | `vec * vec` | `q.dot(a, b)` |

  Compare against `lq.string_null.get()` where the original does.
- Strings: `S("text")`, or `S(loc.LOC_X)`. Where the original juxtaposes literals
  (`LOC_A "\n"`), use comptime concatenation: `S(loc.LOC_A ++ "\n")`.
  `__NULL__` as a string is `lq.string_null.get()`; as a function it's
  `null` (see above).
- Frames: `[$f, next] { body }` is already generated as `state(.f, next);`, and
  you translate `body` after it. A bare `$f` in code is `fr(.f)`. `[0, next]`
  (numeric frames) is generated as `q.setState(0, q.func(next))`.
- Control flow:
  - `do { } while (c)` → `while (true) { ...; if (!c) break; }`.
  - `switch` on floats → Zig `switch` on `@as(i32, @intFromFloat(x))`, or an
    if-chain. `switch` on strings → an if-chain of `.eql`.
  - `for (float i = 0; ...)` → `var i: f32 = 0; while (...) : (i += 1)`.
- Keep QuakeC's float arithmetic exactly. Don't introduce integer shortcuts
  that change results (e.g. replacing `floor(random() * n)` with integer
  maths), and keep calls to `rint`, `floor`, `random` and the like as builtins.
- Constants written as top-level `float NAME = value;` are already `pub const`.
- `#define`d function-like macros (`deathmatch_settings.qc`) become
  `pub inline fn NAME() bool`, used as `if (NAME())`.
- Struct arrays (`intermission_levels[]` in `client.qc`): use a comptime Zig
  array of plain Zig values (`[]const u8` for strings) and `inline for` over it,
  calling `S(entry.map_name)` inside the loop.
- Keep the original comments (`/* */` doc comments above functions become `///`)
  and copy each file's license header into its `//!` header, as in `subs.zig`.
- **Don't restructure code to make the generated QuakeC nicer**, and don't
  duplicate code. Translate straightforwardly.

## Checking your work

From `lq-zig/`:
- `zig build` type-checks everything. Zig only analyses what's referenced, but
  every stub is exported, so all of them are checked. Zig stops at the first
  few errors per pass, so iterate until it's clean.
- Other people are translating other files in the same directory at the same
  time, so `zig build` may report errors in files that aren't yours. Ignore
  those. Your files just need to have no errors of their own. Use
  `zig ast-check src/<file>.zig` for quick syntax checks, and
  `zig fmt src/<file>.zig` before you finish.
- If `zig build` crashes (segfault) or hangs for more than about 5 minutes,
  stop and report it instead of retrying.
- `grep -n "TODO(translate)" src/<your files>` must come back empty when you're
  done.
- Don't run `zig-qc build`, `wasm-opt` or `fteqcc` yourself unless you're asked
  to. The integrator does that once everything is in.
- Only edit your own files. If you think something outside them is wrong (in
  `lq.zig`, generated declarations, or other modules), say so in your report
  instead of changing it.
